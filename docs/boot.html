Installed boot

Limine reads limine.conf off the ESP. Three copies exist (root, boot copy, EFI copy) so BIOS and UEFI both find one:

timeout: 3
serial: yes
textmode: yes
interface_branding: FreeLinX 1.3.1

/FreeLinX 1.3.1
    protocol: linux
    kernel_path: boot():/boot/bzImage
    cmdline: root=PARTUUID=... rootfstype=ext4 rootwait ro init=/init console=ttyS0,115200 console=tty0

/Rescue shell
    cmdline: ... flx.rescue=1

textmode: yes hands BIOS a text screen instead of a framebuffer, so vgacon has a console whether or not a KMS driver shows up. Ignored on UEFI, which has no text mode to hand over.

/init

The kernel mounts the root read-only itself — storage drivers and ext4 are compiled in, no initramfs. Then /init:

  1. checks the root with e2fsck -p,
  2. remounts it read-write before writing anything (a mkdir on the read-only root once ended /init and panicked the kernel — ordering matters),
  3. mounts /home by its pinned UUID,
  4. starts runsvdir, which starts the services.

Rescue (flx.rescue=1) skips the services and gives a root shell. That is also where you go when you forget every password.
