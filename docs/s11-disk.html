Step 11: setup-disk

The only step that writes to a disk. First question: how should the system be stored — run from RAM, or install onto a disk. RAM is the default, on purpose. An installer that defaults to a disk is an installer that eats laptops.

Choosing

Found disks are listed with sizes and models. You pick one, or leave it alone. Mounted filesystems stop the install — partitioning a live system is how an upgrade destroys itself. Then the warning, then the word:

about to erase /dev/sda, and everything on it
This erases /dev/sda, type 'yes' to continue

Anything but yes exactly, and nothing happens. A dry run mode prints every destructive step and does none of them, so the plan can be checked before committing.

What it writes

Partitioning is done by flxpart, four partitions (see disk layout). Then:

mkfs.fat -F 32 -n FLX_BOOT   # the ESP
mkfs.ext4 -F -q -L FLX_ROOT   # /
mkfs.ext4 -F -q -L FLX_HOME   # /home

The running system is copied over with tar, minus the kernel's trees (proc sys dev run tmp), mount points and /home. Hard links and setuid bits survive — the test suite checks both. Then the kernel and Limine go on the ESP, a limine.conf with root=PARTUUID= is written three times over (root, boot copy, EFI copy), and BIOS is pointed at its partition. Homes move to FLX_HOME with owner and 700 fixed per user.

Cleanup of the live session

The live user must not reach the installed system: strip_live takes live out of passwd, shadow and group, drops the passwordless doas rule, and deletes /home/live. The banner is rewritten too — "nothing is kept until it is installed" read on an installed machine would be the opposite of the truth.
