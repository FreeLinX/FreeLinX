FreeLinX base

Version 1.3.1 (stable). Download · Source

FreeLinX without a desktop: a shell on the console, xpkg for everything else. Linux 6.18, a NetBSD userland, musl, LLVM-built, no GNU code.

What is on it

  • System: runit, mdevd, dhcpcd, wpa_supplicant and flxwifi, ntpd, dbus, doas, OpenSSH 10.5 (ssh and sshd), curl, git, tmux, htop, nnn, vim (also vi), bc, e2fsprogs, dosfstools.
  • Console: man (mandoc, ~200 NetBSD manual pages), less, ip (iproute2), lsof, mksh as the login shell (arrow keys, history, Tab). /bin/sh stays the NetBSD sh for scripts.
  • Compiler: cc (tcc) with the musl and kernel headers.
  • Installer: xsetup puts the system on a disk; flxupgrade upgrades an installed system from a newer ISO.

No X11, GTK, Mesa or fonts on the image. Everything else comes from the package repository (~428 signed packages).

Real hardware

Write the ISO to a USB stick and boot it. BIOS and UEFI both work. Secure Boot must be off: the image carries Limine directly, no signed shim.

lsblk
sudo dd if=freelinx-base-x86_64.iso of=/dev/sdX bs=4M conv=fsync

Check with lsblk that /dev/sdX is the stick. dd erases it.

The installer looks for real disks only: /dev/sd?, /dev/nvme?n?, /dev/vd?, /dev/xvd?, /dev/mmcblk?. Partitions are never offered. A disk with anything mounted is refused. Nothing is written until you type yes.

Live session

The system is a squashfs on the medium (boot/root.sfs). A small initramfs (flxlive as /init plus a static sh) finds the volume FREELINX_LIVE, mounts the squashfs read-only, puts a tmpfs over it with overlayfs, and hands over to the system's own /init.

RAM holds what the session changes and the page cache, not a copy of the system. It starts in about 60 MB. Changes are kept in RAM, up to 75% of it. Large packages such as Firefox need an installed system, or more RAM.

The live session gives a root shell on the screen (tty1–tty3) and on the serial line. The medium stays reachable at /media/flx, where the installer and flxupgrade look for it.

Install

Boot the ISO and run:

xsetup

Thirteen steps, one question at a time. Each step is recorded in /etc/xsetup.state, so an interrupted install carries on where it stopped.

setup-keymap      setup-hostname    setup-interfaces  setup-passwd
setup-timezone    setup-proxy       setup-ntp         setup-apkrepos
setup-user        setup-sshd        setup-disk        setup-lbu
setup-apkcache
xsetup                  # every step not done yet, in order
xsetup --list           # the steps
xsetup --status         # which are done
xsetup --reset NAME     # forget one step, so it runs again
xsetup setup-sshd       # run one step on its own

setup-disk is the only step that writes to a disk.

Disk layout

PartitionContents
ESP (1 GB, FAT32)the kernel and Limine, for BIOS and UEFI
BIOS boot (1 MB)Limine's BIOS stage
FLX_ROOT (ext4)/: the system
FLX_HOME (ext4)/home

The system partition gets a share of the disk, not a fixed size: 30% (at least 6 GB, at most 64 GB) on disks of 20 GB and more, 40% (at least 3 GB) on smaller ones. /home gets the rest. An install needs at least 8 GB.

/etc/flx-disk and /etc/fstab name both filesystems by UUID, so a stray disk carrying the same labels is never mounted.

Installed boot

The kernel mounts FLX_ROOT read-only (root=PARTUUID=… rootfstype=ext4 rootwait ro init=/init) with no initramfs: storage drivers and ext4 are built in. /init checks it with e2fsck, remounts it read-write, mounts /home by UUID, and starts the services. /tmp is in RAM.

The boot menu has two entries: the system, and a rescue shell (flx.rescue=1) that starts no services and gives a root shell.

The installed system asks for a login on every console. The live user is removed at install time and is never carried over.

After installing

passwd                      # change your password (users go through doas)
doas flxadduser bob         # another user; --admin also allows doas
doas xpkg install tmux      # packages; doas xpkg upgrade updates them

Only users in wheel can use doas. setup-user asks whether the first user should be one.

Network: wired interfaces take DHCP or a static address via /etc/dhcpcd.conf. Wi-Fi SSID and passphrase go to /etc/wpa_supplicant/flxwifi.conf (0600, passwords in the clear); the flxwifi service connects at boot. SSH host keys are generated once per machine at setup time, never shipped in the image.

A desktop

xpkg install xorg xinit openbox      # pulls in fonts, st and the keymaps
startx

Right-click the desktop for the menu. Without ~/.xinitrc, startx starts openbox with an st terminal. Your own ~/.xinitrc should end in exec openbox --startup st: a terminal started next to openbox can otherwise come up before openbox manages the screen and never show.

xpkg install xrandr
xrandr -s 1920x1080
xpkg install firefox

Upgrading

Boot the new release's ISO on the installed machine and run:

flxupgrade
doas xpkg upgrade

It replaces the system files (/usr /bin /sbin /lib, /init), adds the /etc files the new release has and yours lacks, and puts the new kernel and Limine on the boot partition. Your /etc settings, users, packages and /home stay.

Packages

xpkg install <name> installs from the signed repository (~428 packages). The index signature is checked against /etc/xpkg/keys/freelinx.pub (Ed25519); each archive is checked by sha256. The repository address lives in /etc/xpkg/repos.conf and is set by setup-apkrepos.

Services

FreeLinX uses runit, not OpenRC. Enabling a service is a symlink:

ln -sfn /etc/svc/ntpd /var/service/ntpd

/etc/svc holds the definitions, /var/service is what runit runs. setup-ntp and setup-sshd manage these links. ntpd is on by default. The console is var/service/shell: exec /sbin/flxconsole, a login on an installed system, a shell on the live medium.

Building

The build runs on any x86_64 Linux machine. It needs no root and no built desktop.

1. Host tools (Debian/Ubuntu names):

sudo apt install git curl python3 openssl xorriso squashfs-tools cpio xz-utils binutils

2. The sources, next to each other:

mkdir FreeLinX && cd FreeLinX
for r in FreeLinX-base src ports drivers; do
    git clone https://github.com/FreeLinX/$r.git
done

3. The FreeLinX toolchain (clang + LLD + a musl sysroot):

curl -LO https://github.com/FreeLinX/toolchain/releases/download/v1.0.0/toolchain.tar.gz
tar -xzf toolchain.tar.gz           # -> FreeLinX/toolchain/
FreeLinX/
├── FreeLinX-base/   this repository: the build, the installer, the tests
├── src/             the root filesystem
├── ports/           console ports (mandoc, less, mksh, tcc, ...)
├── drivers/         Limine (bootloader/limine-binary)
└── toolchain/       clang, lld, the musl sysroot
cd FreeLinX-base
sh build-base.sh            # -> out/freelinx-base-x86_64.iso (+ .sha256)

scripts/mkrootfs.sh copies src/rootfs, installs the kept packages by name from the signed repository (so the image has a package database), adds the console ports and manual pages, and trims what a console system does not use. The kernel is the linux package's own, so it matches /lib/modules. The medium is a Limine ISO for BIOS and UEFI.

No GNU

scripts/check-nognu.sh refuses any rootfs carrying GNU toolchain or glibc output. Every ELF file is checked for: a GCC .comment, an interpreter other than musl's /lib/ld-musl-x86_64.so.1, DT_NEEDED on glibc/GCC runtimes, GLIBC_ symbol versions, GNU libraries (ncurses, readline, gettext, …), and GNU code linked in statically, by fingerprint. Current result: 0 failing.
