Build

Any x86_64 Linux machine. No root. No built desktop needed.

Needs

sudo apt install git curl python3 openssl xorriso squashfs-tools cpio xz-utils binutils
mkdir FreeLinX && cd FreeLinX
for r in FreeLinX-base src ports drivers; do
    git clone https://github.com/FreeLinX/$r.git
done

Plus the toolchain release (clang + LLD + musl sysroot) unpacked next to them. Everything else is fetched and checked during the build: the ~26 base packages from the signed repo (Ed25519 index, sha256 per archive), a host xpkg if the machine has none, and one tarball for the file database, by recorded hash. Every input can be pointed elsewhere with environment variables — a build that only works on the machine it was written on is broken.

cd FreeLinX-base
sh build-base.sh            # -> out/freelinx-base-x86_64.iso (+ .sha256)

A few minutes, ~150 MB of downloads.

What it does

  1. mkrootfs.sh: copies src/rootfs, installs the kept packages by name so the image has a package database, adds the console ports and ~200 manual pages with an index, fixes shells (mksh for people, NetBSD sh for scripts), wires xsetup in, trims the rest.
  2. Kernel: the linux package's own bzImage, so it matches /lib/modules. One version in the modules dir or the build refuses.
  3. Medium: the system packed as squashfs (zstd), a ~300 KB initramfs (flxlive + static sh, xz with CRC32 — what the kernel's decoder accepts), Limine for BIOS and UEFI, volume label FREELINX_LIVE, sha256 beside the ISO.

Gates

The build stops when: the source tree has uncommitted changes, flxconsole would give an installed system a shell instead of a login, any program needs a missing library, any graphical program is left, or check-nognu finds GNU code. ALLOW_DIRTY=1 is for test builds only.

Options

VariableEffect
SERIAL=1console on ttyS0 too
OUT=path.isowhere the ISO goes
FLX_HW_TARBALL=…newer firmware than the package carries
BASE_FROM_DESKTOP=1build from a built desktop tree instead
